问题：在 macOS ARM64 上，一个 Python C 扩展在特定 NumPy 操作后静默崩溃，无报错，直接 Segmentation fault。  

逐步推理：  
1. **现象锚定** – 崩溃发生在 `PyArray_SimpleNewFromData` 调用后，且仅当数据缓冲区来自自定义内存池。  
2. **环境差异** – Intel Mac 正常运行。ARM64 指针宽度相同，怀疑内存对齐或结构体填充差异。  
3. **检查崩溃点** – lldb backtrace 指向 `memcpy` 内部，说明访问了无效地址。  
4. **数据流追踪** – 自定义内存池返回的地址是 16 字节对齐，但 NumPy 默认期望 64 字节对齐（ARM64 VM 需求）。  
5. **验证** – 强制内存池返回 64 字节对齐地址后崩溃消失。  
6. **根因** – ARM64 的 `dc zva` 指令在 `memcpy` 中要求目标地址 64 字节对齐，低对齐导致写回时污染相邻内存。  

最终不是 Python 层的逻辑错误，而是底层 ABI 对齐约定比 x86 更严格。
